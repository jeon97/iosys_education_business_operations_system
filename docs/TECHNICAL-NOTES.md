# 설계하면서 확인한 점

## 정원 확인과 신청 저장의 경쟁 조건

정원을 조회한 뒤 신청을 저장하기 전 다른 신청이 들어올 수 있습니다. 단순 화면 확인만으로는 초과 신청을 막을 수 없으므로 저장 시점의 재검증과 데이터베이스 잠금 또는 원자적 조건 갱신이 필요합니다.

## 예산 변경 이력 보존

현재 예산만 저장하면 변경 사유와 승인 과정을 확인할 수 없습니다. 변경 요청은 원본 예산과 분리하고 이전 상태, 작업자, 변경 시각, 승인·반려 사유를 이력으로 남겨야 합니다.

## 외부 알림 실패와 업무 처리 분리

메일 발송 실패 때문에 이미 정상 저장된 신청이나 상태 변경을 취소해서는 안 됩니다. 업무 데이터 저장과 알림 발송 결과를 분리하고 실패 알림은 재처리할 수 있어야 합니다.

## 지금 다시 만든다면

- 정원 차감을 조건부 갱신으로 처리해 동시 신청을 제어합니다.
- 예산 변경을 명시적인 상태 전이 모델로 관리합니다.
- 메일 발송을 메시지 큐 기반 비동기 작업으로 분리합니다.
- 엑셀·보고서 생성을 비동기 작업으로 전환하고 진행 상태를 제공합니다.
- 승인·반려·출력 작업에 감사 로그를 남깁니다.
